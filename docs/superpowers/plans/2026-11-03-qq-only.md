# QQ-only DSH Implementation Plan

> For agentic workers: use subagent-driven-development for the independent tasks.

**Goal:** Deliver the user's QQ-only fork and an installable package with native
interactions, menu management and rich-message capabilities.

**Architecture:** Keep the upstream QQ/DSH bridge, remove unrelated channel
entrypoints and dependencies, and extend the existing QQ runtime. REST-only
management and outbound media reuse its current bot; all interactions stay on
its single Gateway connection.

**Tech Stack:** Node >=22.19, ESM, React settings UI, esbuild,
`@tencent-connect/qqbot-nodejs@1.0.4`, Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-03-qq-only-design.md`.

## Global constraints

- Work on `feat/qq-only-enhancements`, preserve upstream attribution.
- Deliver fork and tarball only; no live QQ or DSH installation.
- No secret values in source, tests, logs, package contents or RPC results.
- Callback actor/route data comes from the event, never from button payloads.
- Menu writes require explicit UI or management requests.
- Preserve existing QQ command and final-answer behavior.
